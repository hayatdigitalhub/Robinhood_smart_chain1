# Robinhood Chain Smart-Money Convergence Bot V1

Paper/research-only monitoring engine. It has **NO private key** and cannot trade.

## What V1 does

- Monitors the five configured smart-money wallets through an Alchemy Address Activity webhook.
- Fetches each transaction receipt directly from Robinhood Chain RPC.
- Classifies a BUY only when the monitored wallet receives a non-quote ERC-20 **and** the same wallet sends a configured quote asset or native ETH in the same transaction.
- Stores trades idempotently by `tx_hash + wallet + token + side`.
- Requires wallet convergence inside `CONVERGENCE_WINDOW_MINUTES` (default 60 minutes), rather than counting unrelated historical buys forever.
- Uses Robinhood Chain-only DexScreener market data.
- Applies a score threshold and alert cooldown before sending Telegram alerts.

## Important limitations

BUY classification is still a **transfer-pattern heuristic**. It is not a full DEX execution decoder. A transaction containing both an incoming token and outgoing quote transfer can still be ambiguous in unusual contracts. V2 should add explicit decoding for known DEX/router/aggregator calls, historical backtesting, holder growth, contract risk, wallet clustering, and richer market/liquidity analysis.

# Windows

# macOS/Linux
source .venv/bin/activate
pip install -r requirements.txt

python seed_wallets.py

## Production

```bash
gunicorn --bind 0.0.0.0:8080 --workers 1 --threads 4 app:app
```

## Alchemy

Create a **Robinhood Mainnet Address Activity** webhook and add the five wallets listed in `config.py`.

Webhook URL:

```text
https://YOUR-HOST/webhook/alchemy
```

Set `ALCHEMY_WEBHOOK_SIGNING_KEY` to the signing key generated by Alchemy. The webhook endpoint verifies `X-Alchemy-Signature` when that variable is set.

## Telegram

Create a bot with `@BotFather`, send `/start` to it, obtain your chat ID, then set:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

## Render

Push this folder to GitHub, create a Render Web Service from the repository, add the environment variables, and deploy.

Health check:

```text
https://YOUR-SERVICE.onrender.com/health
```

Alchemy webhook:

```text
https://YOUR-SERVICE.onrender.com/webhook/alchemy
```

## Testing

The engine has been syntax-checked and tested with isolated runtime fakes for:

- multiple smart wallets in the same transaction;
- BUY classification requiring both token inflow and quote/native outflow;
- convergence-window filtering;
- SQLite alert cooldown handling;
- duplicate trade protection.

For production validation, replay several real Robinhood Chain transactions from the monitored wallets and compare the engine's classification with the transaction traces/events on the block explorer.
